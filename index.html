A bug that only showed up in production

      

        Coolify's healthcheck kept failing with connection refused
        — over and over, ten attempts, every deploy. But nginx's own logs
        showed it starting cleanly with no errors. The container was fine.
        The healthcheck's address wasn't.
      


      

        

          
Dockerfile

          
 EXPOSE 80

          
 

          
-HEALTHCHECK ... CMD wget -q --spider http://localhost/ || exit 1

          
+HEALTHCHECK ... CMD wget -q --spider http://127.0.0.1/ || exit 1

        


        

          
nginx.conf

          
 server {

          
     listen 80;

          
+    listen [::]:80;

          
     server_name _;

        

      


      

        nginx's alpine image only auto-adds an IPv6 listener when its default
        config is left untouched — ours wasn't. Inside the container,
        localhost resolved to ::1 first, so the
        healthcheck's own request found nothing listening and failed
        instantly, even though the site was serving fine on IPv4 the whole
        time. Found by reading the entrypoint log line that said exactly
        that, not by guessing and retrying.
